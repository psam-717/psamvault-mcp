# Skills

These pages are **skills**: procedures written to be *executed* by an AI agent — Hermes, Claude Code,
Codex, Cursor, Goose, or any agent that can read files and run shell commands — rather than read as
narrative documentation. Each one states when to load it, the steps to take, and how the agent knows it is
done.

**This folder is the single source for those procedures.** The repository-root [`SKILL.md`](../SKILL.md) is
an index into it, and the documentation site renders these same files. A change to how something is done is
made here — in one file — and nowhere else.

## The set

| Skill | Load it when | Page |
|---|---|---|
| **Install** | the user wants psamvault-mcp wired into an MCP host for the first time | [install.md](./install.md) |
| **Upgrade** | the server is already installed and a newer version is wanted, or the install is broken | [upgrade.md](./upgrade.md) |
| **Use the tools** | the agent has to use a stored credential: a site login, an authenticated API call, injecting a secret, scanning a project | [usage.md](./usage.md) |

## How an agent should use this folder

1. Pick the skill by its trigger — installing, upgrading, or using a credential.
2. Follow that skill's steps in order; each one names its own definition of done.
3. Follow its links only for depth (a tool's exact parameters, a workflow's failure modes) — do not read
   the whole folder.
4. Do not restate a procedure in another file. If it changed, the skill changed.

## Keeping the installed copy and these pages in step

Both copies are edit points: the **installed skill** (`HERMES_HOME/skills/psam-custom/psamvault-mcp/SKILL.md`)
is what an agent loads on a machine, and it is edited there; these pages are what the repository and the
documentation site publish, and they are edited here. Neither is generated from the other — they are
**merged**, with `git merge-file` and a recorded base:

```bash
python scripts/sync-skill-docs.py --check     # in step? exit 1 if not (also fails on conflicts)
python scripts/sync-skill-docs.py --pull      # this page's edits -> the installed skill
python scripts/sync-skill-docs.py --publish   # the installed skill's edits -> these pages [--commit [--push]]
python scripts/sync-skill-docs.py --init      # record the baseline commit (after committing pages)
```

Shared text lives between markers, one pair per section:

```markdown
<!-- section:usage/pitfalls -->
…text kept in step with the installed skill…
<!-- /section:usage/pitfalls -->
```

The section id names the page it belongs to, which is what lets the tool split one installed file across
three pages. The heading line stays **outside** the markers, so this page may present a section
differently from the installed skill without that registering as a difference — and anything else outside
(the front matter, a "See also" list) is furniture that exists only here and is never touched.

Rules worth knowing:

- a section marked on **one** side only is local to that side and is never moved;
- an unclosed marker, a duplicate id, or an id whose page does not match the file is an error, and nothing
  is written;
- two edits to the **same line** are a conflict: the tool writes nothing and prints both versions for a
  human to choose. It never picks a winner.

### The distribution mirror

A third copy exists for maintainers: a local checkout that `compat --sync-skill` can install from
(the directory name is `private-skills`, beside a psamvault-mcp checkout, or whatever
`PSAMVAULT_SKILL_CLONE` points at). It is **not** an edit point and **not** a public install step —
public users follow the pages in this directory, and a missing Hermes skill is not drift. The
checkout is a mirror, regenerated by `--publish` from the installed skill and committed on its own
branch. The mirror check reports it as `in step`, `stale` or `missing` and fails on drift, so the
copy that gets distributed can no longer differ from the copy that runs while both claim the same
version.

```bash
python scripts/sync-skill-docs.py --init --mirror <path-to>/private-skills/psamvault-mcp/SKILL.md
python scripts/sync-skill-docs.py --publish --commit --push    # regenerates it and opens a branch/PR
```

## Not published here: release and publishing skills

The skills for *cutting a release* — version bump, contract entry, TestPyPI/PyPI upload, GitHub release,
sandbox verification — are maintainer-only and deliberately excluded from this repository's skill set.
Nothing in them is needed to install, upgrade or use the server. The parts a user does need (installing,
proving which version is live, upgrading safely) are in [install.md](./install.md) and
[upgrade.md](./upgrade.md).
